# Rainer's MoonCake —— 更离谱的点子集

> 前提认知：铜块梗之所以好笑，是因为它是**正交轴的组合爆炸**——
> 氧化度(4) × 涂蜡(2) × 形态(块/切制/雕纹/台阶/楼梯/门/活板门/格栅/栏杆/灯笼/避雷针…) × 材质(铜/铜傀儡/铜箱…)。
> 所以下面所有点子的评价标准只有一条：**它能不能自动生成更多笑话**。
> 一次性的玩笑只是段子，能组合出几千个名字的才是模组。

> **另一条同样重要的前提：抽象是玩法层面的，不是性能层面的。**
> 这个模组可以很离谱，但不能让游戏变卡。详见下面的「性能红线」。

---

## ⚠️ 性能红线（硬约束）

### 三条铁律

**1. 变体走数据驱动，不手写代码，也不给每个变体独立贴图**

真正贵的从来不是"方块种类多"——原版自己有几千个 blockstate，几百个月饼变体对注册表毫无压力。
贵的是这三样：**BlockEntity**、**每 tick 的逻辑**、**每个变体一张独立贴图**。

所以：
- 变体由**数据包 + 轴定义**生成，不写几百个 `register()`
- 贴图走**调色板 + 程序化合成**，一套基础贴图染出所有变体
- 能用一个方块 + blockstate 属性表达的，就别拆成两个方块

**2. 绝不做每 tick 的逻辑**

- **氧化**：复用原版铜的 **random tick（随机刻）** 机制，不要自己每帧遍历
- **月饼块一律不用 BlockEntity**；需要存的东西（馅料/象限/内容物）存在**物品侧**的 `DataComponent` 里
- 任何计时用 `Level#scheduleTick`，不要自己维护全局计数器
- 不要写"每 tick 扫描全世界找月饼"这类代码

**3. 程序化贴图只在资源重载时算一次**

四象限混色如果每帧实时计算，帧率会死。正确做法：在**模型烘焙阶段**算好并缓存，
运行时只查表。

### ✅ 允许

- 几百个方块/物品变体（原版量级，没问题）
- 少量自定义实体（玉兔 / 月饼傀儡）
- 粒子效果（注意别每帧刷几十个）
- 一次性高开销（例如首次加载时烘焙模型）——只要不是**持续**开销

### ❌ 不允许

- 每 tick 遍历全世界的月饼块算氧化
- 每个变体一张独立贴图
- 每帧动态生成模型/贴图
- 会自然生成、会无限增殖的月饼方块
- 月饼实体无限堆积（扔出去的月饼必须会消失）

### 道歉的艺术

既然答应了要道歉，就道一个**又真诚又好笑**的：

```
[mooncake_overflow/ERROR] 对不起。
[mooncake_overflow/ERROR] 我们本来打算加 347 个变体。
[mooncake_overflow/ERROR] 但那样你的帧率会掉。所以我们决定慢慢来。
[mooncake_overflow/ERROR] 这是一封道歉信。
```

配置项 `logApology = true`（默认 `true`，因为这是模组的灵魂）。

## 〇、核心建议：把"月饼"做成一套正交轴系统

不要一个一个手写物品。定义轴，然后让名字和效果自动生成。

| 轴 | 取值 | 说明 |
|---|---|---|
| 馅料 | 可可豆 / 南瓜 / 莲蓉 / 五仁 / 豆沙 / 西瓜 / 紫颂果 / … | 决定基础效果 |
| 氧化度 | 铜 / 斑驳 / 锈蚀 / 氧化 | 对应铜的 4 阶段 |
| 涂蜡 | 是 / 否 | 用蜜脾右键，锁死氧化度 |
| 加工形态 | 面团 / 生胚 / 烤熟 / 切制 / 竖半砖 / 月饼块 / 台阶 / 楼梯 / … | 复刻铜块全套形态 |
| 象限 | 1/4、2/4、3/4、4/4，**每象限独立记录馅料和氧化度** | 见第三节 |
| 内容物 | 任意物品的 `DataComponent` | 见第五节 |

生成出来的名字会长这样：

```
涂蜡的斑驳的切制莲蓉半月月饼
氧化五仁竖半砖月饼
涂蜡的锈蚀的雕纹可可豆月饼块楼梯
```

**这里就藏着这个模组最抽象的一个点**：名字长度会随轴数指数增长，最后**超出 tooltip 宽度、溢出屏幕**。
建议真的放任它溢出，然后加一个成就叫 **「名称溢出」**，描述写「你已经分不清自己在做什么了」。

技术提示：26.1 用 `Identifier`（不是 `ResourceLocation`），物品状态用 `DataComponentType` 而不是 NBT。
轴组合建议**数据包驱动**，玩家能自己注册馅料 → 变体数量无限，且**零额外代码成本**。

## 一、把梗完整复刻一遍：**月饼块全家桶**

9 个月饼 → 1 个 **月饼块**。然后：

- 月饼块会像铜块一样**真的随时间氧化**（4 阶段，用随机刻），涂蜡能永久锁住
- 用**切石机**切 → 切制月饼块（和切制铜块同款操作，逻辑自洽）
- 切制月饼块 → 月饼台阶 / 月饼楼梯 / 月饼墙
- 雕纹月饼块（用月饼模具右键）
- 月饼活板门、月饼门、月饼格栅、月饼栏杆、月饼链、月饼灯笼、月饼避雷针
- **铜傀儡月饼**：铜月饼当铜傀儡的头 → 召唤出「月饼傀儡」，走路掉月饼渣
- 避雷针月饼被雷劈 → 「雷击月饼」，吃了给抗性提升但会持续引雷

> **性能说明**：这一堆听起来吓人，但每个变体只是「同一个方块 / blockstate 属性的不同取值」，
> 配上**调色板染色**的共享贴图，实际开销和原版铜块家族是同一量级。放心做。

配套的笑点：模组启动时打印那封**道歉信**（见上）。它道歉的不是"加了太多"，
而是**"本来想加更多，为了你的帧率忍住了"**——这比真的做 347 个更好笑，也更体面。

## 二、氧化是真的 / 铜月饼的硬度是有道理的

你原案里"铜月饼吃了扣 1 点血，因为太硬"——这个可以做得非常自洽：

- **硬度即氧化度**：铜月饼（最软）扣 0.5 ❤ → 氧化月饼（最硬）扣 3 ❤，但饱食度也递增
- **涂蜡 = 食品级封蜡**：涂蜡后不再扣血（蜡包住了）
- **斑驳/锈蚀阶段会掉月饼屑**：拿着走会在地上留下粒子，猪会来吃
- **吃氧化月饼会中毒**（铜锈），但能获得"铜臭味"效果，村民交易打折
- **切制铜月饼 = 已经帮你切好了**，吃了不扣血（因为薄了），但饱食度只有 1/4

## 三、切开的月饼：**四象限独立系统**（你原案里最疯的一条，建议重点做）

用剑/切石机切月饼 → 变成 4 个 1/4 块，**每个象限独立保留自己的馅料和氧化度**。
然后可以拼回去，拼出「1/4 斑驳可可豆 + 1/4 氧化莲蓉 + 1/4 五仁 + 1/4 铜南瓜」这种缝合怪。

在此基础上继续发疯：

1. **每象限独立结算效果** → 一块月饼可以同时给你 4 种 buff 和 3 种 debuff
2. **颜色由四象限混合** → 贴图程序化生成（16 种馅料² × 4 氧化度²…组合爆炸，
   所以**必须**程序化画 + 在烘焙阶段缓存，不能每帧算也不能一张张画）
3. **「五仁」的真面目**：只要四个象限是四种不同的仁，就自动命名为「五仁月饼」（明明只有四种）
4. 用**切石机**切可以指定切法：十字切 / 对角切 / 横切 → 切成"半月"、"三角月饼"、"月饼条"
5. **对角线切的月饼可以当飞镖**（形状尖）

## 四、月饼是**容器**：往里塞任何东西

月饼做成像潜影盒一样能装东西的容器，但**打开的唯一方式是吃掉它**。

- 塞火药 → **爆炸月饼**，吃下去在嘴里炸
- 塞末影珍珠 → 吃了瞬移，落点随机（可能塞进基岩）
- 塞唱片 → 吃了开始放歌，且无法停止
- 塞一把剑 → 「月饼里藏刀」，吃完获得伤害加成，但也割伤自己
- 塞一个苦力怕头 → 吃完你会开始害怕猫
- 塞一个下界之星 → 极贵，吃完获得"月饼之神"，但会被所有猪灵敌视
- 塞另一个月饼 → **套娃**，理论无限层，每层递减效果但 nobody stops you

> 实现提示：内容物存 `DataComponent`，**不引入 BlockEntity**。

## 五、月亮系统：**你可以把月亮吃掉**

- 月饼效果与**当前月相**绑定：满月翻倍，新月完全无效（"空月饼"）
- 新月时吃月饼 → **真的吃掉月亮的一小块**，月相推进一格
- 于是玩家可以**把月亮一点一点吃光**：世界变黑、怪物不再燃烧、刷怪率上升
- 吃光后：天上只剩一个牙印。放一个月饼在祭坛上献祭可以"吐回来"
- **月饼雨**：月相异常时会下月饼雨，被砸到受伤（流星月饼，直接砸出坑）

> 实现提示：月相是全局状态，可以用**世界数据（SavedData）**存，不要每 tick 重算。
> 月饼雨是偶发事件，不要常驻粒子。

## 六、玉兔 / 嫦娥 / 后羿（中秋神话的抽象化）

- **祭月**：在地上放月饼，等月亮升起 → 玉兔出现，拿东西给它，它**捣**成别的东西（赌博机：投入 1 个，随机产出，可能什么都没有）
- **玉兔是黑心商人**：交易汇率极度离谱，但偶尔白送
- **嫦娥**：在 y>320 放月饼召唤，她会**偷走你的月饼**然后给你一只兔子
- **后羿射日反过来**：用弩发射月饼可以把太阳射下来 → 短暂日食 / 永久黑夜
- **吴刚砍桂树**：砍树时会有个 NPC 一直在旁边砍同一棵树，永远砍不倒

> 实现提示：玉兔是**唯一**值得做 BlockEntity/Entity 的部分，但也别让它每 tick 做重活。

## 七、五仁月饼：作为"禁忌"存在

- 五仁月饼是**最强的月饼**，但吃下去随机触发 5 种效果之一，其中一种是**直接死亡**
- 村民看到你拿五仁月饼 → 交易价格随机 ±50%
- 给猪喂五仁月饼 → 猪会变成僵尸猪灵（跨维度）
- 成就：**「五仁月饼其实很好吃」**（描述：「你在骗谁？」）
- 反过来：**甜月饼党 vs 咸月饼党**——吃咸月饼会激怒甜党村民，反之亦然，两派会打起来

## 八、月饼的社交属性（中秋的本质是送礼）

- **月饼礼盒**：能装 4/6/9 个月饼，带缎带，可以送人（右键玩家 → 对方收到礼盒）
- **礼盒会转赠**：A 送给 B，B 再送给 C，盒子记录传递链，tooltip 显示"历经 7 手"
- **发霉**：礼盒放久了会发霉，转赠时对方会看到"这个礼盒已经转过 12 手了"
- **月饼当货币**：村民以月饼交易，月饼是硬通货
- **贿赂怪物**：给僵尸月饼，它会放过你（僵尸会坐下来吃）
- **在月饼上写字**：模具上刻字 → 印出来的月饼带字，可以写"中秋快乐"

## 九、元游戏：模组会看着你

- 统计玩家吃了多少月饼，成就树从「尝了一口」到「你就是月饼」
- 吃满 100 个 → 游戏内提示：**「你已经做了 100 个月饼了。你还好吗？」**
- 吃满 1000 个 → 玩家名字旁边永久显示一个月饼图标，无法移除
- **自指合成**：月饼 + 月饼 = 更大月饼；月饼 + 月饼模具 = 印着月饼的月饼
- **逆向合成**：在工作台里放一个月饼，会拆成原料，但**数量不对**（熵增/熵减），偶尔拆出一个完全无关的东西
- **保质期**：月饼有游戏内天数，过期变质；放冰箱（冰+箱子）延长；过期月饼能酿「月饼酒」
- **饱食度溢出**：吃得太饱，饥饿条图标**变成月饼**，且不再下降

## 十、战斗与物理

- **回旋镖月饼**：扔出去会飞回来，附「忠诚」可以远程回旋
- **月饼盾**：拿月饼格挡，每次格挡掉一块"馅"（象限系统刚好用得上）
- **月饼地雷**：放地上当压力板，踩上去滑倒
- **月饼压路机**：从高处落到月饼上会弹起，可以叠很多个月饼做弹跳床
- **弩的弹药**：月饼当弩箭伤害翻倍（你原案已有），**附「多重射击」= 一次射三个月饼**
- **月饼粒子**：吃月饼时嘴部喷月饼渣，可当武器（致盲对手）

> 实现提示：扔出去的月饼实体必须设置寿命上限并在落地后消失，否则会堆积。

## 十一、竖半砖的复仇

梗的原点是「竖半砖会带来无数变体」。所以：

- 真的加一个 **竖半砖月饼**（半块月饼竖着放的方块）
- 它没有任何实际用途，但**有 4 种氧化度 × 2 涂蜡 × 8 种馅料 = 64 个变体**
- tooltip 里写：`「我们知道这会增加内存占用。我们不在乎。」`
- 成就：**「竖半砖」**（描述：「你终于还是做了」）

> 当然，"不在乎"是角色扮演。真做的时候它就是一个 blockstate 属性 + 调色板染色，成本极低。

## 建议的实现顺序（MVP）

1. **月饼本体**：面团 → 模具 → 压印 → 烤制 → 可食用（你原案的 1–6 步，先把工艺链跑通）
2. **氧化系统**：铜/斑驳/锈蚀/氧化 + 蜜脾涂蜡 + 切石机切制（复用原版铜的逻辑，性价比最高）
3. **象限系统**：切开 / 拼合 / 每象限独立馅料（这是最独一无二的卖点）
4. **月饼块全家桶**：数据包驱动，自动生成形态矩阵
5. **月亮系统**：吃月亮（最有戏剧性，做完直接有宣传点）
6. 玉兔 / 五仁 / 礼盒 / 元游戏嘲讽（锦上添花）

> 这个顺序的原则是：**每一阶段结束时都留在一个性能安全的状态**，
> 不会出现"做了一半发现框架撑不住"。

## 命名与技术备注

- 模组名 **Mooncake Overflow**（月饼溢出），副标题 *347 Variants, None of Them Good*
- 模组 id `mooncake_overflow`，主包 `org.cvrain.mooncakeoverflow`
- 26.1 用 `Identifier`（旧版 `ResourceLocation` 已改名）
- 物品状态用 `DataComponentType`（旧版 NBT）
- 轴驱动的变体建议走 **数据包 + 注册表**，这样玩家能加自己的馅料，且不会把代码写成 3000 行
- 区块方块用 `BlockBehaviour.Properties.of().setId(...)`（26.1 起必须显式给 id）
